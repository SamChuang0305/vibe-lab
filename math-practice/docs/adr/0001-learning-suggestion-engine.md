# ADR 0001: 作答結果學習建議引擎（Rule-based）

- 狀態：Accepted
- 日期：2026-02-23
- 決策者：vibe-lab/math-practice 維護者

## 背景

專案在結果頁已提供完整題目列表與分數，但缺少「下一步應該怎麼練」的引導。  
使用者需求是：根據題目列表中的作答狀況（答錯、答對但作答時間過長），在結果頁題目列表下方新增「學習建議」區塊，並提供可直接套用思路的關卡設定建議。

## 決策

採用**規則式（Rule-based）學習建議引擎**，在前端即時計算，不新增後端或外部服務依賴。

### 核心判定方式

按題目種類（`add/sub/mul/div`）分組統計：

- `total`：該題型題數
- `wrong`：答錯、超時、未作答
- `slowCorrect`：答對但作答秒數超過門檻
- `wrongRate = wrong / total`
- `slowRate = slowCorrect / total`
- `avgSec`：平均作答秒數

### 門檻設定（MVP v1）

- 最小樣本數：`minSamples = 3`
- 錯誤率：
  - 高：`>= 0.40`
  - 中：`>= 0.25`
- 偏慢率：
  - 高：`>= 0.40`
  - 中：`>= 0.25`
- 答對偏慢秒數門檻：
  - 加法：`8` 秒
  - 減法：`10` 秒
  - 乘法：`12` 秒
  - 除法：`14` 秒

### 建議產生策略

- 錯誤率高且偏慢率高：先「正確率強化」（無限時、降難度），再「速度強化」（8~12 秒）。
- 錯誤率高：優先給單題型、低壓（無限時）與降難度建議。
- 錯誤率中：給單題型穩定化建議（15~20 題，時間先放寬）。
- 偏慢率中/高：給單題型限時 8~12 秒提速建議。
- 無明顯弱點：顯示維持設定、增加題量的提示。

### UI 呈現策略

- 位置：結果頁「題目列表」下方。
- 呈現：卡片清單（觀察、建議關卡、練習目標）。
- 顯示上限：最多 `3` 則建議（依優先級排序）。

## 為何不選擇其他方案

### 方案 A：手動固定建議（不分析作答資料）

- 優點：實作最快。
- 缺點：缺乏個人化，價值有限。
- 決議：不採用。

### 方案 B：ML/LLM 驅動建議

- 優點：可高度彈性、語意豐富。
- 缺點：成本高、可解釋性低、資料與隱私議題增加。
- 決議：目前不採用，先以可解釋的規則式 MVP 上線。

## 影響與後續

### 正面影響

- 使用者完成作答後可立即獲得可行練習策略。
- 決策可解釋、可在 README 與程式碼中明確追蹤。
- 不增加部署複雜度。

### 風險與限制

- 門檻屬經驗值，可能需依實際使用數據調整。
- 沒有跨回合歷史資料時，建議僅依單次作答判定。

### 延伸方向

- 新增「一鍵套用建議關卡」。
- 加入跨回合歷史資料與趨勢追蹤，調整建議權重。
- 將規則參數外部化（例如 JSON 設定）以便 A/B 測試。
